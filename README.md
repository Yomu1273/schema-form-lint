# schema-form-lint

Static checks for [JSON Forms](https://jsonforms.io) and [react-jsonschema-form](https://rjsf-team.github.io/react-jsonschema-form/) configs. It finds the bugs that make a form unsubmittable or silently ignore your settings, before a user hits them.

```text
error   jsonforms/required-hideable  uischema.json#/elements/4/elements/0
        `goodwillReason` is required, but a SHOW rule at `/elements/4/rule` can hide it.
        JSON Forms still validates hidden fields, so the form can't be submitted while
        this field is hidden and empty.

error   jsonforms/impossible-condition  uischema.json#/elements/4/rule/condition/schema
        This condition can never be true: "Goodwill" is not one of the values the field
        allows ("warranty", "goodwill"). As a result, the element is always hidden.
```

Zero runtime dependencies. Works on hand-written configs and on configs generated by an LLM: the JSON output gives a model stable rule IDs, paths, and fixes it can act on.

## Install

```sh
npm install --save-dev schema-form-lint
```

## CLI

```sh
npx schema-form-lint jsonforms --schema schema.json --uischema uischema.json
npx schema-form-lint rjsf --schema schema.json --ui-schema ui-schema.json
```

| Option | Description |
| --- | --- |
| `--format text\|json` | Output format. Default `text`. |
| `--custom-widgets a,b` | RJSF widget names you register through the `widgets` prop. |
| `--rule <id>=<off\|warning\|error>` | Change one rule. Repeat the flag to change more than one. A typo in the id is an error. |
| `--max-warnings n` | Fail when there are more than `n` warnings. Warnings do not fail the command unless this is set. |

Exit codes: `0` clean, `1` problems found, `2` usage or input error.

## API

```ts
import { formatText, lintJsonForms, lintRjsf } from "schema-form-lint";

const diagnostics = lintJsonForms({
  schema,
  uischema,
  // Turn this off when the app already drops validation errors for hidden fields.
  rules: { "jsonforms/required-hideable": "off" },
});
// or: lintRjsf({ schema, uiSchema, customWidgets: ["StarRating"] })

console.log(formatText(diagnostics));
```

Each diagnostic has `ruleId`, `severity`, `document` (`"schema"` or `"uischema"`), a JSON Pointer `path`, a `message`, and usually a `suggestion`.

## Rules

### Schema (both libraries)

| Rule | Severity | Catches |
| --- | --- | --- |
| `schema/unknown-required` | error | `required` (including `then`/`else` and `dependentRequired`) names a property that doesn't exist, so no field is rendered for it and the form can't be submitted. |
| `schema/unknown-dependency` | warning | `dependentRequired`/`dependencies` keyed on a property that doesn't exist, so it never triggers. |

### JSON Forms

| Rule | Severity | Catches |
| --- | --- | --- |
| `jsonforms/unresolved-scope` | error | A control or rule scope that doesn't resolve in the schema. Suggests the closest property. |
| `jsonforms/required-hideable` | error | A field that is required for every input, has no default, and a SHOW/HIDE rule (on the control or any ancestor layout) can hide. Names required only inside `then`, `oneOf`, or `dependentRequired` are not included. Set it to `off` when hidden-field errors are already filtered. |
| `jsonforms/required-disableable` | warning | The same, for ENABLE/DISABLE rules. |
| `jsonforms/impossible-condition` | error | A condition that can't match real input: a value outside the field's `enum`, the wrong type, an empty `enum`, or contradictory ranges. It also explains whether the condition still passes while the field is empty. |
| `jsonforms/empty-field-passes` | warning | A scoped condition without `failWhenUndefined`, so the rule applies before the user has answered. |
| `jsonforms/null-means-absent` | warning | `const: null` used to detect an empty field. JSON Forms leaves unanswered fields undefined, not null. |
| `jsonforms/unknown-effect` | error | A rule effect that isn't SHOW, HIDE, ENABLE, or DISABLE. |
| `jsonforms/duplicate-control` | warning | Two controls bound to the same scope. |

Scopes inside array `options.detail` layouts resolve against the item schema, and local `$ref`s are followed.

### react-jsonschema-form

| Rule | Severity | Catches |
| --- | --- | --- |
| `rjsf/unknown-ui-key` | error | A uiSchema key that matches no property, so its settings are silently ignored. Properties that only exist in `dependencies`, `allOf`/`oneOf`/`anyOf`, or `then`/`else` branches count as known. |
| `rjsf/unknown-order-entry` | warning | A `ui:order` entry that isn't a property. RJSF drops it. The form still renders. Not reported for open objects (`additionalProperties` or `patternProperties`), because those names can exist at runtime. |
| `rjsf/incomplete-order` | error | `ui:order` misses a property that is always present (including properties added by `allOf`) and has no `"*"` wildcard. RJSF throws and renders an error instead of the form. |
| `rjsf/multiple-order-wildcards` | error | More than one `"*"` in `ui:order`. RJSF throws. |
| `rjsf/unresolved-definition` | error | A root `ui:definitions` key that doesn't resolve, or that no schema `$ref` uses. RJSF matches these keys against `$ref` strings, so the uiSchema is never applied. Keys that do match are linted. |
| `rjsf/hidden-required` | error | A required field (including a requirement that comes from `allOf`) with the `hidden` widget and no default. |
| `rjsf/widget-type-mismatch` | error | A built-in widget used with a type it doesn't support, such as `textarea` on an integer. Skipped for names you pass in `customWidgets`. Names that aren't built-ins are assumed to be registered. |

## Design principles

- **No false alarms over full coverage.** A check only reports what it can prove from the config. Anything it can't analyze is skipped.
- **Explain the consequence.** Every message says what the user of the form will experience, not only what's wrong in the JSON.
- **Machine-readable.** Stable rule IDs and JSON Pointer paths, so CI and code-generating agents can consume the output.
